# Доменная модель

Доменная модель описывает основные сущности системы подачи заявок на финансирование проектов, их атрибуты и взаимосвязи.

Модель построена вокруг сущности **FinancialRequest**, которая объединяет данные заявки, проект, участников процесса, документы, результаты экспертиз и историю прохождения процесса.


## Логика модели

Центральной сущностью является `FinancialRequest`.

Вокруг неё выделены четыре основных группы данных:

1. **Данные заявки** — сама заявка и связанный проект.
2. **Участники и документы** — пользователи, роли и документы заявки.
3. **Результаты рассмотрения** — экспертные и финансовые заключения.
4. **Процесс обработки** — текущий экземпляр процесса и история его переходов.

## 4.3. Управление процессом

### RequestProcessContext

<details>
  <summary> <b>Контекст процесса</b> </summary>

Контекст экземпляра бизнес-процесса конкретной заявки.

| Атрибут              | Тип              | Описание                          |
| -------------------- | ---------------- | --------------------------------- |
| `id`                 | int              | Идентификатор экземпляра процесса |
| `FinancialRequest`   | FinancialRequest | Заявка                            |
| `ProcessVersion`     | String           | Версия процесса                   |
| `CurrentResponsible` | User             | Текущий ответственный             |
| `StartedAt`          | DateTime         | Дата запуска процесса             |
| `UpdatedAt`          | DateTime         | Дата последнего изменения         |
| `CompletedAt`        | DateTime         | Дата завершения процесса          |
| `IsActive`           | bool             | Признак активного процесса        |

`RequestProcessContext` представляет текущий экземпляр процесса, связанный с заявкой. Исторические переходы не хранятся в контексте, а фиксируются в `RequestProcessHistory`.

---------------

</details>

### RequestProcessHistory

<details>
  <summary> <b>История процесса</b> </summary>

История переходов заявки между этапами и статусами.

| Атрибут                 | Тип                   | Описание                           |
| ----------------------- | --------------------- | ---------------------------------- |
| `id`                    | int                   | Идентификатор записи               |
| `RequestProcessContext` | RequestProcessContext | Экземпляр процесса                 |
| `FromStage`             | Stage                 | Предыдущий этап                    |

| `ToStatus`              | Status                | Новый статус                       |

История позволяет восстановить последовательность обработки заявки, включая возвраты на доработку и повторную подачу.

---------------

</details>

## 4.4. Перечисления

### Status

<details>
  <summary> <b>Статус</b> </summary>

Текущий статус заявки:

* `Draft` — черновик;
* `Consideration` — на рассмотрении;
* `Returned` — возвращена на доработку;
* `OnApproval` — на утверждении;
* `Accepted` — утверждена.

---------------

</details>

### Stage

<details>
  <summary> <b>Стадия</b> </summary>

Текущий этап процесса:

* `Preparation` — подготовка заявки;
* `ExpertReview` — экспертная проверка;
* `FinancialReview` — финансовая экспертиза;
* `Approval` — согласование;
* `FinalApproval` — утверждение.

---------------

</details>

### ProcessAction

<details>
  <summary> <b>Действие процесса</b> </summary>

Действие, вызвавшее переход процесса:

* `Created` — создание;
* `Submitted` — подача;
* `Assigned` — назначение ответственного;
* `Approved` — согласование/утверждение;
* `Returned` — возврат на доработку;
* `Rejected` — отклонение;
* `Resubmitted` — повторная подача;
* `Completed` — завершение процесса.

---------------

</details>

Дополнительные пояснения:

* `FinancialRequest` ссылается на `User` как на автора заявки;
* `Project` ссылается на `User` как на автора/ответственного;
* `ExpertReview` и `FinancialReview` ссылаются на пользователей, выполнивших соответствующую экспертизу;
* `RequestProcessContext` содержит текущего ответственного пользователя;
* `RequestProcessHistory` фиксирует пользователя, выполнившего конкретное действие.
