# Проектирование информационной системы

Демонстрационный кейс по проектированию корпоративной информационной системы управления ресурсами компании.

Система предназначена для управления сотрудниками, проектами, бюджетами и заявками на расходы.

Кейс показывает полный цикл работы системного аналитика:

**требования → бизнес-процессы → доменная модель → БД → API → интеграции → архитектура**

---

## 1. Описание системы

Система используется для управления проектами и связанными с ними ресурсами.

Основные функции:

* ведение сотрудников и организационной структуры;
* создание и сопровождение проектов;
* назначение сотрудников на проекты и роли;
* формирование бюджетов проектов;
* создание и согласование заявок на расходы;
* контроль доступности бюджета;
* предоставление данных через API;
* взаимодействие с внешними системами.

## 2. Основные участники

| Роль                 | Основные действия                               |
| -------------------- | ----------------------------------------------- |
| Сотрудник            | Создание заявок на расходы                      |
| Руководитель проекта | Управление проектом и согласование заявок       |
| Финансовый контролёр | Контроль бюджета и финансовых параметров        |
| Администратор        | Управление пользователями, ролями и настройками |

## 3. Основные сущности

Предварительная доменная модель включает:

* **Сотрудник**
* **Подразделение**
* **Проект**
* **Роль проекта**
* **Назначение сотрудника**
* **Бюджет**
* **Заявка на расход**
* **Статья расходов**
* **Пользователь**
* **Роль доступа**

Связи и бизнес-правила между сущностями будут подробно рассмотрены в доменной модели и ERD.

---

## 4. Основной бизнес-сценарий

Ключевой сценарий системы — обработка заявки на расход по проекту.

**Уполномоченный пользователь создаёт заявку → система проверяет данные и доступность бюджета → определяет маршрут согласования → руководитель проекта согласовывает заявку → финансовый контролёр выполняет проверку → система резервирует сумму в бюджете.**

Заявка содержит:

* проект;
* статью расходов;
* сумму;
* описание;
* плановую дату;
* дополнительные документы.

Система контролирует:

* корректность данных;
* доступность бюджета;
* полномочия пользователя;
* допустимые переходы между статусами;
* отсутствие дублирования заявок.

### Контроль бюджета

Доступная сумма определяется с учётом уже зарезервированных средств:

**Доступный бюджет = Плановый бюджет − Зарезервировано**

Если сумма заявки превышает доступный бюджет, заявка не может быть отправлена на согласование.

## 5. Что проектируется в рамках кейса

### Требования

Функциональные требования, бизнес-правила, ограничения и критерии приёмки.

### Бизнес-процессы

BPMN-модели:

* создание заявки;
* согласование заявки;
* резервирование бюджета.

### Доменная модель

Сущности, атрибуты, связи, состояния и бизнес-правила.

### База данных

Реляционная модель, ключи, ограничения, индексы и нормализация.

### API

REST API, контракты, валидация, ошибки и авторизация.

### Интеграции

Взаимодействие с внешними системами посредством REST и RabbitMQ.

### Архитектура

Компоненты системы и взаимодействие между сервисами, БД и внешними системами.
