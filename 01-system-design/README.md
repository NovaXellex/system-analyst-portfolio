# Проектирование информационной системы

Демонстрационный кейс по проектированию корпоративной информационной системы управления ресурсами компании.

Система предназначена для управления сотрудниками, организационной структурой, проектами, бюджетами и финансовыми операциями.

Кейс показывает полный цикл работы системного аналитика:

**требования → бизнес-процессы → доменная модель → БД → API → интеграции → архитектура**

---

## 1. Описание системы

Компания использует информационную систему для управления проектной деятельностью и связанными с ней ресурсами.

В системе необходимо:

* вести реестр сотрудников и организационную структуру;
* создавать и сопровождать проекты;
* назначать сотрудников на проекты и роли;
* формировать бюджеты проектов;
* регистрировать финансовые операции и расходы;
* контролировать доступность бюджета;
* согласовывать заявки на расходы;
* рассчитывать плановые и фактические показатели;
* предоставлять данные через API;
* передавать информацию во внешние системы.

---

## 2. Основные участники

В системе предусмотрены следующие роли:

| Роль                 | Основные действия                                                  |
| -------------------- | ------------------------------------------------------------------ |
| Сотрудник            | Создание заявок на расходы, просмотр собственных данных и проектов |
| Руководитель проекта | Управление проектом, сотрудниками и согласование заявок            |
| Финансовый контролёр | Контроль бюджета и финансовых параметров заявок                    |
| Бухгалтер            | Работа с проведёнными финансовыми операциями                       |
| Администратор        | Управление пользователями, ролями и настройками                    |

## 4. Основной бизнес-сценарий

Ключевой сценарий системы — обработка заявки на расход по проекту.

**Уполномоченный пользователь создаёт заявку на расход → система проверяет данные и доступность бюджета → определяет маршрут согласования → руководитель проекта согласовывает заявку → финансовый контролёр проверяет финансовые параметры → система резервирует сумму в бюджете → после фактического проведения операции обновляет фактические затраты.**

Заявка может содержать:

* проект;
* статью расходов;
* сумму;
* описание расхода;
* плановую дату;
* дополнительные документы.

В процессе система должна контролировать:

* обязательность и корректность данных;
* доступность бюджета;
* полномочия пользователя;
* допустимые переходы между статусами;
* отсутствие дублирования операций;
* согласованность плановых и фактических показателей.

### Контроль доступности бюджета

При проверке заявки система учитывает не только общий бюджет проекта, но и уже зарезервированные и фактически израсходованные средства.

**Доступный бюджет = Плановый бюджет − Зарезервировано − Фактически израсходовано**

Например:

* плановый бюджет — 10 млн;
* зарезервировано — 6 млн;
* фактически израсходовано — 2 млн;
* доступный бюджет — 2 млн.

При создании заявки на 2,5 млн система должна определить недостаточность доступного бюджета и не допустить её дальнейшее согласование.

## 5. Что проектируется в рамках кейса

### Требования

Формализация функциональных требований, бизнес-правил, ограничений и критериев приёмки.

### Бизнес-процессы

Моделирование основных процессов в BPMN 2.0:

* создание заявки на расход;
* согласование заявки;
* резервирование бюджета;
* проведение финансовой операции;
* обновление бюджета.

### Доменная модель

Проработка:

* сущностей;
* атрибутов;
* связей;
* состояний;
* бизнес-правил;
* производных показателей.

### База данных

Проектирование реляционной модели:

* таблицы;
* первичные и внешние ключи;
* ограничения;
* индексы;
* нормализация.

### API

Проектирование REST API:

* ресурсы и операции;
* структуры запросов и ответов;
* валидация;
* ошибки;
* статусы;
* авторизация.

### Интеграции

Предусматривается взаимодействие с внешними системами:

* HR-системой;
* бухгалтерской системой.

Для интеграций рассматриваются синхронное REST-взаимодействие и асинхронная передача событий через RabbitMQ.

### Архитектура

Проработка взаимодействия компонентов системы, сервисов, базы данных и внешних систем.
