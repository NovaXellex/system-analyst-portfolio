## Представленный кейс

### Система подачи заявок на финансирование проектов

Профильная enterprise-система для подачи, проверки и согласования заявок на финансирование проектов.

Кейс построен как единая сквозная цепочка:

**система → требования → бизнес-процессы → доменная модель → БД → API → интеграции → архитектура**

Каждый следующий раздел развивается на основе предыдущего.

### 01 — Система → [Описание системы](./01-Описание%20системы.md)

Назначение системы, участники процесса, основные функции и границы системы.

### 02 — Требования и сценарии → [Требования и сценарии](./02-Требования%20и%20сценарии.md)

Роли, User Story, Use Case, функциональные и нефункциональные требования.

### 03 — Бизнес-процессы → [Бизнес-процессы](./03-Бизнес-процесс.md)

Основной процесс обработки заявки в BPMN и ключевые бизнес-правила.

### 04 — Доменная модель → [Доменная модель](./04-Доменная%20модель.md)

Основные сущности предметной области, их атрибуты, связи и состояние заявки на разных этапах процесса.

### 05 — База данных → [База данных](./05-База%20данных.md)

Реляционная модель PostgreSQL, ERD, структура таблиц, связи и ограничения целостности.

### 06 — API → [API](./06-API.md)

REST API: ресурсы, бизнес-операции, API-контракты, параметры запросов, ответы и управление состоянием заявки.

### 07 — Интеграции → [Интеграции](./07-Интеграции.md)

Взаимодействие внешними системами, включая синхронные и асинхронные сценарии, идемпотентность и обработку ошибок.

### 08 — Архитектура → [Архитектура](./08-Архитектура.md)

C4-модели системы, API Gateway, PostgreSQL, RabbitMQ, фоновые воркеры и взаимодействие с внешними системами.

---

## Что демонстрирует кейс

* анализ предметной области;
* формирование и декомпозицию требований;
* описание User Story и Use Case;
* моделирование бизнес-процессов в BPMN;
* формирование бизнес-правил;
* проектирование доменной модели;
* проектирование реляционной БД и ERD;
* проектирование REST API и бизнес-операций;
* проектирование межсистемного взаимодействия;
* применение асинхронного взаимодействия через брокер сообщений;
* идемпотентность и повторную обработку сообщений;
* проектирование архитектуры с использованием C4;
* трассируемость решений от требований до технической реализации.

## Архитектурные решения

В кейсе показаны:

* REST API;
* API Gateway;
* PostgreSQL;
* RabbitMQ;
* Integration Worker;
* Notification Worker;
* Identity Provider;
* внешнее файловое хранилище;
* внешняя финансовая система;
* retry и Dead Letter Queue для асинхронных операций;
* идемпотентная обработка интеграционных сообщений.
