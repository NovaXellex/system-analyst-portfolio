# Системный аналитик

Добро пожаловать в моё портфолио системного анализа.

Здесь представлен демонстрационный кейс полного цикла проектирования информационной системы — от постановки задачи и требований до API, интеграций и архитектуры.

## Представленный кейс

### Система подачи заявок на финансирование проектов

Небольшая enterprise-система для подачи, проверки и согласования заявок на финансирование проектов.

Кейс построен как единая сквозная цепочка:

**система → требования → бизнес-процессы → доменная модель → БД → API → интеграции → архитектура**

Каждый следующий раздел развивается на основе предыдущего.

### 01 — Система → [Описание системы](./01-Описание%20системы.md)

Описание назначения системы, участников, основных функций и границ системы.

### 02 — Требования и сценарии → [Требования и сценарии](./02-Требования%20и%20сценарии.md)

Роли и права доступа, User Story, Use Case, функциональные и нефункциональные требования.

### 03 — Бизнес-процессы → [Бизнес-процессы](./03-Бизнес-процессы.md)

Основной процесс обработки заявки в BPMN и ключевые бизнес-правила.

### 04 — Доменная модель → [Доменная модель](./04-Доменная%20модель.md)

Основные сущности предметной области, их атрибуты, связи и бизнес-логика.

### 05 — База данных → [База данных](./05-База%20данных.md)

Реляционная модель данных, ERD, структура таблиц, связи и ограничения.

### 06 — API → [API](./06-API.md)

REST API системы: эндпоинты, API-контракты, структуры запросов и ответов, валидация и обработка ошибок.

### 07 — Интеграции → [Интеграции](./07-Интеграции.md)

Взаимодействие с внешними системами, синхронные и асинхронные сценарии, передача финансовых данных и обработка ошибок.

### 08 — Архитектура → [Архитектура](./08-Архитектура.md)

Архитектура системы и взаимодействие пользовательского интерфейса, backend-компонентов, базы данных и внешних систем.

---

## Что демонстрирует кейс

* анализ предметной области;
* формирование и декомпозицию требований;
* описание User Story и Use Case;
* моделирование бизнес-процессов в BPMN;
* формирование бизнес-правил;
* проектирование доменной модели;
* проектирование реляционной БД и ERD;
* проектирование REST API и контрактов;
* проектирование межсистемного взаимодействия;
* описание архитектуры системы;
* трассируемость решений от требований до технической реализации.
